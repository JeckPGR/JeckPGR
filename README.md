### 🧭 My Philosophy

I believe good software isn't the one with the most features — it's the one that's **simple, reliable, and solves a real problem**. That mindset comes from working across two very different worlds: building **financial and utility systems** where accuracy can't be compromised, and building **F&B applications** where speed and usability under pressure matter most.

That contrast shaped how I build:

- **Clarity over cleverness** — clean, readable code beats clever one-liners nobody can maintain.
- **Solve the real problem first** — I focus on what a system needs to *do*, before deciding what tech to use to do it.
- **Low-code isn't lazy code** — through **Digitra**, I'm exploring how to make digital solutions accessible without sacrificing quality, because not everyone needs a custom-built app to solve their problem.
- **Structure first, UI second** — a solid relational database schema is the foundation everything else stands on.

Off the keyboard, I apply the same mindset elsewhere: **badminton** teaches split-second decision making, **analyzing e-sports gameplay** trains me to break down strategy and patterns, and **hiking** is a reminder that consistent, steady progress beats rushing.
